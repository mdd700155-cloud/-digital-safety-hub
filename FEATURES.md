# Digital Safety Hub — Feature List

A user-friendly cybersecurity web application that helps everyday users check suspicious messages, URLs, screenshots, QR codes, voice recordings, and deepfakes, understand potential risks, and receive actionable safety or recovery guidance.

> **Check → Understand → Protect → Recover**

## Scam Check

Route: `/check`

| Feature | Details |
| --- | --- |
| Input modes (6 tabs) | **Message** (textarea), **URL/link** (text input), **Screenshot** (image upload), **QR code** (live camera scanner), **Audio/Voice** (upload or recording), **Deepfake Image** (image upload) |
| Image upload | Drag-and-drop style upload with preview, 5 MB size limit, client-side validation |
| QR scanning | Live camera scanning powered by `html5-qrcode`, with a manual-entry fallback |
| Voice — upload | Drag-and-drop audio upload: WAV, MP3, M4A, OGG, or WebM (max 12 MB, up to 3 minutes) |
| Voice — recording | In-browser recorder via `MediaRecorder` (mic permission requested only on click, live timer, graceful denial message) |
| Voice — preview | Play/pause audio preview plus re-record and delete controls |
| Voice — analysis | Unified analyzer sends audio to **two engines in parallel** — scam analysis and deepfake detection; client converts browser-recorded WebM to 16 kHz WAV for compatibility |
| Voice — transcript | Word-for-word transcript generated by Google Gemini, shown with **clickable highlights** on suspicious phrases that reveal why each was flagged |
| Voice — scam fingerprint | Bars showing each detected signal with its computed confidence (derived from real pattern matches, never fabricated) |
| Voice — result | Risk card (Safe / Suspicious / High Risk), **likely scam type** (with uncertainty note when pattern match is weak), plain-language summary, "Why was this flagged?" evidence breakdown, and audio metadata footer |
| Voice — protection | HIGH_RISK results show "What should you do now?" — 7 numbered steps incl. the 1930 helpline and cybercrime.gov.in |
| Voice — evidence export | Save audio, transcript (TXT), full analysis (JSON), and a summary image (PNG) — all generated locally |
| Voice — honesty | Clearly labels that transcription is AI-generated; never claims a call is "definitely a scam" and never fabricates confidence values |
| Deepfake image tab | Upload a photo for forensic tamper/AI-generation analysis via `DeepfakeImageDetector` (own upload + analyze controls, max 10 MB) |
| Analysis trigger | Explicit "Analyze" action per tab; loading state with spinner while running |
| Result card | Color-coded risk card (green / yellow / red) with: |
| — Risk level | **Safe** ("No obvious threat detected"), **Suspicious**, or **High Risk** |
| — Confidence | Low / Medium / High |
| — Summary | Plain-language explanation of the result |
| — Warning indicators | Specific reasons the content was flagged |
| — Recommendations | Concrete next steps for the user |
| — Signals | Raw signals collected during analysis |
| — Threat intelligence | Shows when a public threat-intel match (e.g., URLhaus) was found |
| Error state | Friendly error message when analysis fails; analysis history is not persisted |
| Layout | Two-column desktop layout with a sticky "What can you check?" rail; single column on mobile |

## Deepfake Detection

Detects AI-manipulated or AI-generated content across both images and audio, using client-side forensic feature extraction combined with server-side analysis.

### Image deepfake detection

Route: `/api/analyze/deepfake-image` (POST, multipart)

| Feature | Details |
| --- | --- |
| Upload | Photo upload with preview (max 10 MB, image files only), canvas capped at 1024×1024 for smooth processing |
| Client-side feature extraction | `extractDeepfakeImageFeatures` runs in the browser on the image pixels (metadata, noise/ELA-style analysis, compression artifacts) |
| Server-side analysis | `analyzeDeepfakeImage` combines the submitted client feature scores with structural checks and returns a final verdict |
| Result card | `DeepfakeImageResult` shows the aggregate likelihood, per-feature scores, and plain-language explanation with honest caveats |

### Audio deepfake detection

Route: `/api/analyze/deepfake` (POST, multipart)

| Feature | Details |
| --- | --- |
| Feature extraction | Client extracts acoustic features from the waveform (spectral stats, pitch/energy variance, signal anomalies) before upload |
| Server-side analysis | `analyzeDeepfakeAudio` merges client features with server-side file/format checks into a deepfake likelihood verdict |
| Unified result | Runs alongside voice scam analysis (see Scam Check) via `UnifiedAudioAnalyzer`; `UnifiedAudioResult` presents both verdicts side by side |
| Honesty | Deepfake scores are heuristic likelihoods, clearly labeled — never presented as definitive proof |

## Analysis Engine

Routes: `/api/analyze` (POST), `/api/analyze/voice` (POST, multipart), `/api/analyze/deepfake` (POST, multipart), and `/api/analyze/deepfake-image` (POST, multipart)

| Feature | Details |
| --- | --- |
| Input validation | Request body validated with `zod` (type + content), untrusted input handled safely |
| URL normalization | Incoming URLs are normalized and parsed before checks |
| Structural heuristics | Rule-based signals: URL anomalies, malformed URLs, suspicious keywords/patterns in messages, image/QR metadata |
| AI analysis (optional) | Google Gemini (`@google/genai`) analyzes content when `GEMINI_API_KEY` is set — **server-side only**, the key is never exposed to the client |
| ML URL classifier | Optional local ML classifier for URL risk scoring |
| Threat intelligence | `URLhaus` lookup to check whether a URL is listed as malicious |
| Risk aggregator | Combines all signals into a final verdict: `SAFE` / `SUSPICIOUS` / `HIGH_RISK` |
| Voice — file validation | Magic-byte sniffing (RIFF/ID3/ftyp/EBML/OggS) — the real format is verified from the file contents, never trusted from the extension alone |
| Voice — transcription | `gemini-3.6-flash` transcribes audio (with `gemini-3.5-flash` and `gemini-flash-latest` as automatic fallbacks) into a structured, validated JSON result |
| Voice — signal engine | Deterministic pattern detection over the transcript: **19 signal definitions** (urgency, fear, threats, authority/government impersonation, OTP/credential requests, payment instructions, remote access, links, account suspension, rewards, fake support, digital arrest, investment, job, delivery) |
| Voice — scam typing | Likely scam category chosen from the strongest signal family (Bank/UPI Fraud, OTP Theft, Digital Arrest, Fake Customer Support, etc.), marked **uncertain** when support is weak |
| Voice — aggregation | Signal strengths map into the shared risk aggregator (STRONG/MODERATE/WEAK weights); Gemini alone cannot force HIGH_RISK |
| AI resilience | Transient 503 "high demand" / 429 rate-limit errors retry automatically (3 attempts × 3 models with 1s–3s backoff) before an honest failure is reported |
| Graceful fallback | If AI/ML/intel are unavailable, analysis continues with structural heuristics and the response **honestly states** that AI was unavailable — no fabricated results |
| Privacy | Only the submitted content is sent to the API; nothing is stored (audio is processed in memory and discarded) |

## ScamWatch

Route: `/scamwatch`

Anonymous community feed where users share suspicious messages, URLs, and descriptions so others can recognize ongoing scams.

| Feature | Details |
| --- | --- |
| Anonymous reporting | "Warn the Community" form (scam type, risk level, message, URL, description) inserts into a Supabase `scam_reports` table — no login or identity required |
| Community stats | Live stat cards: total reports, High Risk count, Suspicious count, and Trending (seen ≥ 3 times) |
| Report cards | Risk badge, scam type, reported time, copyable suspicious message, copyable URL (with "do not open" warning), "What happened?" description |
| Community signal | "Seen by N people" counter with an "I've Seen This Too" button (tracked locally per device via `localStorage`) and Trending badge |
| Search & filter | Live text search across type/message/URL/description plus a risk-level dropdown filter |
| Safety warning | High-risk reports show a prominent "Stay safe" callout (don't click links, share OTPs, or send money) |
| Pre-filled from analysis | Scam Check results can carry scam type / risk level / message / URL into the report form via query params |
| Loading & empty states | Spinner while fetching, friendly empty states for "no reports yet" and "no matching reports" |

## Privacy & Honesty Principles

- **No login, no accounts, no tracking** — everything is usable without sign-up.
- **No analysis data storage** — submitted content is never persisted server-side; uploaded audio/images are processed in memory and discarded after analysis.
- **Community reports are stored (anonymously)** — ScamWatch submissions are saved to a Supabase `scam_reports` table with no name, email, or identity attached; anyone can browse and confirm reports.
- **Voice privacy** — audio is sent to Google's Gemini API for transcription only; the recording never leaves the user's device except for that single analysis call.
- **Local generation** — incident reports are generated in the browser and stay on the device.
- **Server-side secrets** — API keys (e.g., Gemini) live only in `.env.local` on the server; never in client code.
- **Validated input** — all user input and external API responses are treated as untrusted and validated.
- **Honest results** — the app never claims anything is "100% safe" and never fabricates analysis results or confidence scores. When AI is unavailable it says so explicitly.
- **No fake functionality** — all buttons and links lead to real, working actions or official resources.
